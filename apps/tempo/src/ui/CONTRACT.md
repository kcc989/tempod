# UI contract

The foundation that the four region workers build on. Paths are relative to `apps/tempo/src/`; `~/` is the same folder in imports. Spec: `docs/04 UI.md`, plus 02, 03, 05 (UI rules) and the web items of 07, and the Git Forge extension.

Rules for every region:

- Call server functions only through `call()` or the hooks in `ui/hooks/useCall.ts`. Errors are `TempoError` with the error-table message.
- Use the primitives in `ui/components/ui/` and theme tokens only (no hex). Dense, 13 px base, colour only for state.
- Every control is keyboard reachable with a visible focus ring. Copy is short, plain, sentence case.
- Keep shared state in `ui/state/workspace-ui.ts`. Keep region-local state local. No Redux, Zustand or similar.
- `localStorage` only through `ui/lib/storage.ts` or `useLocalStorage`, only for layout, sort order, viewed marks, composer drafts and per-browser preferences.

## Shared state: `ui/state/workspace-ui.ts`

Framework-free stores (`Store` from `ui/lib/store.ts`). React reads them with the hooks in `ui/hooks/useWorkspaceUi.ts`.

**Chat and document tabs** (per workspace, in memory)

- `CenterTab = {kind: "chat", sessionId} | {kind: "file", path, line: number | null} | {kind: "diff", path: string | null} | {kind: "browser", url} | {kind: "liveView"} | {kind: "guide"} | {kind: "artifact", artifactId, version: number | null}`. Desktop chat tabs render in the center; document tabs render in the tool area.
- `tabKey(tab)`: identity. `chat:<id>`, `file:<path>`, `diff` (one diff tab), `browser:<url>`, `liveView` (one Live View tab), `guide` (one Guide tab), `artifact:<artifactId>` (one tab per artifact).
- `tabRef(tab)` / `parseTabRef(ref)`: the string form `chat:<sessionId>`, `file:<path>:<line?>`, `diff:<path?>`, `browser:<url>`, `liveView:`, `guide:`, `artifact:<artifactId>:<version?>`.
- `openTab(ws, tab, {activate?})`, `openFile(ws, path, line?)`, `openDiff(ws, path?)`, `openBrowser(ws, url)`, `openLiveView(ws)`, `openGuide(ws)`, `openArtifactTab(ws, artifactId, version?)`: open or update in place; bump `seq`; return the key.
- `closeTab(ws, key)`, `activateTab(ws, key)`, `cycleTab(ws, 1 | -1, chatOnly?)`, `moveTab(ws, key, index)`, `syncChatTabs(ws, sessionIds)`. Workspace next/previous shortcuts pass `chatOnly: true`.
- `targetChatSession(state)`: the active chat, else the chat shown last.

**Composer insertions**

- `ComposerInsertion = {kind: "mention", path} | {kind: "reviewComments", commentIds} | {kind: "text", text}`.
- `insertIntoComposer(ws, insertion, sessionId?)`: queues it for that session (default: target chat), shows that chat and bumps `composerFocusSeq`.
- `takeInsertions(ws, sessionId)`: removes and returns the session's (and untargeted) insertions.
- `focusComposer(ws)`: ⌥L.

**Panels**

- Per workspace: `diffScope` (`setDiffScope`, `toggleDiffScope`), `rightTab: "changes" | "files" | "checks" | "artifacts"` (`setRightTab`, `showRightTab`), `bottomTab: "setup" | "run" | "terminal"` (`setBottomTab`, `showBottomTab`). Both legacy tab APIs select tools in the right area. `showBottomTab(ws, "setup")` also opens the phone Setup pane.
- `UtilityTab = RightTab | BottomTab`; `toolTabs` starts with Changes and `activeToolKey` starts with `"changes"`. `selectTool(ws, key | null)` opens the right side and selects a utility or the launcher; `closeTool(ws, key)` removes it and shows the launcher if it was active. Document selection uses `activateTab`.
- Global layout (`layoutStore()`, `getLayout()`, `setLayout(patch)`): `sidebarOpen`, `rightOpen`, legacy `bottomOpen` (kept in `tempo:layout:panels`), `phonePane: "chat" | "changes" | "setup"`, `lastWorkspaceId`. `toggleSidebar` (⌘B), `toggleRight` (⌘⌥B), `toggleBottom` (⌥J; opens Terminal, then the launcher), `setPhonePane`. `bottomOpen` no longer controls a rendered lower pane.

**Dialogs**

- `DialogState = {kind: "newWorkspace", projectId?, prompt?} | {kind: "addProject"} | {kind: "settings", tab?, projectId?} | {kind: "diagnostics", workspaceId} | {kind: "environment", workspaceId} | {kind: "palette"} | {kind: "openFile", workspaceId} | {kind: "searchFiles", workspaceId}`. One at a time, except `settings`: it goes to `settingsStore` (the settings page) and stays open under the others.
- `openDialog(state)`, `closeDialog(kind?)`, `dialogStore`, `settingsStore` (`useSettings()`).
- `confirm({title, description?, confirmLabel?, cancelLabel?, destructive?, typeToConfirm?}): Promise<boolean>`; `CONFIRM_TEXT.revert(n)`, `.closeRunningChat()`, `.resetPreviewAccess()`, `.deleteWorkspace(slug)` carry the 04 texts. Archive has no confirmation (Undo toast for 8 s).

## Actions and shortcuts

- `ui/state/actions.ts`: `registerAction(id, handler, {enabled?, fallback?})`, `runAction(id)`, `hasAction(id)`, `availableActions()`. The newest non-fallback registration wins.
- `useAction(id, handler, {enabled?, fallback?})` (`ui/hooks/useActions.ts`): register while mounted. `useAvailableActions()` for the palette.
- The global key listener (`useGlobalShortcuts`, mounted by `AppShell`) runs global bindings from `ui/lib/shortcuts.ts`; only ⌘K works while a modal is open.
- `useShortcuts(handlers, {target?, enabled?, allowPlainInEditable?})` (`ui/hooks/useShortcuts.ts`): scoped bindings (diff J/K/⌃V, composer Enter/⇧Tab/Esc, permission Enter/⌫). Matches `KeyboardEvent.code`; ⌘ = Meta on macOS, Ctrl elsewhere; plain keys do not fire from text fields unless allowed; `preventDefault` unless the handler returns `false`.
- `ShortcutKbd {action}` (`ui/components/ui/kbd.tsx`) shows a binding's label.

Who registers what: shell fallbacks (above); `WorkspaceLayout` (above); region A: `workspace1`–`9`, `nextWorkspace`, `prevWorkspace`, `nextNeedsYou`, `commitPush`, `createPr`, `merge`, `archive`; region B: `newChat`, `closeTab`, `expandAll`, `modelPicker`, `attach`; region D: `toggleRun`.

## Workspace tool area

`ToolPanel {workspaceId}` owns the desktop right tab bar and full-height content area. `toolTabs` contains opened utility tools; `activeToolKey` selects a utility or an open document key, with null showing the launcher. Browser uses the existing `liveView` tab and `getBrowserLiveView`; it is Cloudflare Browser Run. The web-only preview tabs still use `browser`. File, diff, Guide and artifact document keys still use the existing registry. Chat selection and drafts stay independent. Run, Terminal and document bodies remain mounted while another tool is selected and their tabs stay open. Collapsing the whole tool area unmounts `ToolPanel`. `RightPanel` still renders the phone Changes pane. Legacy `bottomOpen` values remain readable; no lower process pane is rendered.

## Repositories (`ui/components/repositories/`)

`/_app/repositories.tsx` exposes `/repositories` with validated search fields `project`, `tab` (`code`, `commits`, `pulls`, `issues`), `ref`, `path`, `file`, `pull` and `issue`. `/_app/workspaces.tsx` exposes the workspace list at `/workspaces` for phone navigation.

`RepositoryHub` lists projects and chooses the repository view. GitHub projects keep their external browsing link. Artifact repository code, bounded file previews and commit history use repository RPCs without a running workspace. An absent selected ref stays absent in requests so an empty repository can show its initial workspace action. The branch picker permits a tag or commit only when its `allowRef` option is true.

`RepositoryForm` creates, publicly imports or links an existing Artifacts repository. `RepositoryPullRequests` provides local PR listing, creation, editing, draft state, close/reopen and workspace reuse/adoption for review and merge. Both forms submit with Command/Ctrl+Enter. Clone URL copying returns only a credential-free URL. `links.ts` routes Artifact project and PR links into Tempo while retaining existing GitHub links. Empty repository bootstrapping and PR review do not require an agent login. Read-only repositories disable editing workspace and PR creation while metadata edits remain available.

`RepositoryIssues` lists, searches and filters owner-operated issues and opens issue details. `IssueForm` creates or edits title, Markdown body and label assignments. `RepositoryIssueComments` adds, edits and deletes comments, with chronological pages of 50 and mutation-driven page adjustment after adding or deleting the final comment on a page. `RepositoryLabelManager` creates, edits and deletes labels; label deletion clears an active filter for that label. All issue metadata functions remain available when Git storage is read-only or the Artifacts binding is unavailable. GitHub repository details link to GitHub issues instead.

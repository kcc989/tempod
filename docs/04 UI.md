# 04 UI

This tab defines the web UI. It follows Conductor's layout and behavior, adapted for a browser.

## Layout

&#91;embedded content: Workspace view wireframe · sidebar, top bar, center tabs, right panels\]

The workspace view has five regions: sidebar, top bar, center tabs, right panel (top) and bottom panel (right, lower half). All panes resize by dragging their edges. Sizes and open or closed panels are kept per browser in `localStorage`, wrapped in `try`/`catch`.

## Sidebar

The sidebar lists every non-archived workspace, grouped by project, and updates live from the hub channel.

- **Sections, top to bottom:** Pinned (only if any workspace is pinned), then one section per project in `sort_order`, then a `History` link at the bottom.
- **Project row:** `owner/name`, a collapse toggle, and a `+` button that opens New workspace with that project picked.
- **Workspace row:**
  - Line 1: status icon (Indicators, below), then the title. The title is bold when attention is `unread` or `needs_input`.
  - Line 2, secondary text: the branch, then `·`, then the slug.
  - Right side: PR badge `#<number>` coloured by `pr_state`, and a checks dot when `checks_state` is set.
- **Order inside a project:** `last_activity_at`, newest first. A header menu switches to `created_at`. The choice is kept in `localStorage`.
- **Hover card** (after 400 ms): state, last activity, PR and checks, and buttons for the next action, Wake or Sleep, and Archive.
- **Right-click menu:** Rename, Pin or Unpin, Copy branch name, Open on GitHub, Archive.
- **History:** a list of archived workspaces with Restore and Delete.
- **Width:** 280 px by default, resizable from 220 to 400 px. `⌘B` hides and shows it.
- Grouping by status is out of scope for version 1.

## Top bar

The top bar names the workspace and offers exactly one primary git action.

- **Left:** the title (click to edit), the branch with a copy button, and `→ <base branch>`. The base branch picker works until a PR exists; it calls `setBaseBranch`.
- **Middle:** one link per detected port, `<port> ↗`. A click opens the preview in a new browser tab. ⌥-click opens it in a Browser tab inside Tempo.
- **Right:** the container pill, the primary action button, and an overflow menu.

**Container pill**

| State | Pill text |
| --- | --- |
| `starting` | `Starting…` plus the current step, for example `Restoring snapshot` |
| `setting_up` | `Running setup` |
| `ready`, `working` | `Running · <instance>` |
| `stopping` | `Going to sleep` |
| `sleeping` | `Sleeping` |
| `error` | `Error`, red |
| `creating` | `Creating` |
| `archiving` | `Archiving` |
| `archived` | `Archived` |

**Primary action.** Show the first row that applies.

| # | Condition | Button | Shortcut |
| --- | --- | --- | --- |
| 1 | Uncommitted changes, or local commits not on origin | Commit and push | ⌥Y |
| 2 | Pushed, no PR | Create PR | ⌥P |

**Overflow menu:** Wake or Sleep, Rotate preview link, Open on GitHub, Copy workspace link, Diagnostics, Archive.

## Center: chat tabs and composer

The center holds tabs: one per open session, plus file, diff and Browser tabs. Each chat tab is one session and one agent.

**Tabs**

- New chat: ⌥T or the `+` button. It opens a menu of the four agents. An agent without a login is shown disabled with `Add login in Settings`.
- Closing a chat tab calls `closeSession`. If a turn is running, confirm first. Closed sessions stay readable under the tab bar's `Closed chats` menu.
- File tabs are read-only in version 1. Diff and Browser tabs are described in the right-panel section.

**Transcript: how each item kind renders**

| Kind | Rendering |
| --- | --- |
| `user_message` | Bubble with the text, mention chips, attachment thumbnails. On hover: time and `Revert to here`, which reverts to this turn's checkpoint. |
| `agent_message` | Markdown (GitHub flavour). Code blocks get syntax highlighting with Shiki and a copy button. A caret shows while `streaming`. |
| `agent_thought` | One collapsed line, `Thinking`, that expands to the text |
| `tool_call` | One row: icon by `toolKind`, title, status. Expands to its content: diffs as unified diffs, terminal output in monospace, text as text. Each location is a link that opens a file tab at that line. ⌃O expands or collapses all. |
| `plan` | A checklist with each entry's status. While the turn runs, a `Plan 3/4` pill also shows above the composer. |
| `permission` | A card with the title and one button per option. Enter picks the first `allow` option; ⌫ picks the first `reject` option. |
| `notice` | A small centred line, grey, amber or red by level |
| `handoff` | A collapsed notice, `Session restarted; transcript handed to the agent`, that expands to the text |
| `revert_marker` | A divider, `Reverted to turn <n>`. Reverted turns show at 50% opacity. |
| `error` | A red card with the message, the code, and a Retry button that resends the same prompt as a new turn |

Under each turn: duration and, if the agent sends usage, tokens.

**Composer**

- Enter sends. ⇧Enter adds a new line.
- While a prompt submission is pending, Enter, Send, Queue and Send now cannot submit another prompt for that session. Switching tabs does not remove this guard. If submission fails, restore the prompt unless the owner has already typed a new draft.
- While a turn runs, Enter queues the prompt. Queued prompts show above the composer as chips; each can be edited, deleted or dragged.
- When the current chat's running adapter advertises steering, show a separate **Send now** button. It delivers the message into that turn without stopping it. Enter still queues. If the turn ends before delivery, the message stays queued. An unconfirmed delivery shows an error and requires the user to check the response before retrying.
- A message with `steeringPending` shows **Sending now**. Disable its queue controls until delivery settles.
- A Stop button shows while a turn runs. Esc in the composer also stops it.
- `@` opens a fuzzy file picker over `listFiles` and inserts a mention chip.
- `/` opens a menu of the agent's own commands plus Tempo's `/plan`, which toggles plan mode. While the menu is open, Up and Down choose an entry, Enter selects it, and Esc closes the menu without stopping the turn.
- Attach with paste, drag and drop, or ⌘U. Each file at most 10 MiB.
- Pickers: model (from the agent's `model` config option) and mode (from the agent's modes). ⇧Tab in the composer toggles plan mode.
- Draft review comments show as one chip, `<n> review comments`. They are sent with the next prompt.
- A context ring shows used and total context when the agent sends `usage_update`.
- The draft text is kept per session in `localStorage`.
- Unsent mention, attachment and review-comment chips stay with their session when switching tabs. Draft storage may include their metadata and server references; file bytes and preview URLs stay in memory.
- Archived workspace: the composer is replaced by `Restore to continue`. Missing login: a banner with `Add login`.

## Right and bottom panels

The right side is for review (top) and processes (bottom). ⌘⌥B toggles the whole right side; ⌥J toggles the bottom panel.

**Changes tab**

- A file list with status letter (`A`, `M`, `D`, `R`) and `+`/`−` counts, from `getChanges`. It refreshes on every `changes` message.
- Scope toggle: `Branch` (against the merge base with `origin/<base>`) or `Uncommitted` (against `HEAD`). ⌥U switches.
- `Group by folder` toggle.
- A click opens the Diff tab at that file.
- Footer: a commit message field and `Commit and push`.

**Diff tab** (center)

- Unified or split view, kept in `localStorage`. Unified only below 1024 px wide.
- J and K move to the next and previous file when focus is not in a text field.
- `Mark as viewed` per file (⌃V). The mark is stored in `localStorage` with the file's diff hash, so it clears when the diff changes.
- Comments: click a line number, or drag across several, to add a comment. A file-level comment button sits in each file header. Comments are `draft` until sent with a prompt.
- A `Send <n> comments to <agent>` button puts the drafts into the composer as one chip.

**All files tab**

- A tree from `listFiles`. A click opens a read-only file tab (`readFile`, Shiki highlighting).
- ⌘P opens a fuzzy file picker. ⌘⇧F searches with `searchFiles`.

**Checks tab**

- PR number, title, state and a link to GitHub.
- One row per check run: name, conclusion, link to its GitHub page. Logs are out of scope for version 1.

**Bottom panel tabs**

- **Setup:** status, the setup output, and `Rerun setup`. After a failure it also shows `Continue anyway`. Settings warnings and errors from all three settings files show here too.
- **Run:** a menu of run scripts, Start and Stop (⌥R toggles the default script), and the live output.
- **Terminal:** tabs `t1` to `t9`, a `+` button, and xterm. On phone width this tab is hidden.

## Dialogs

Every dialog is a shadcn/ui `Dialog`. ⌘Enter submits; Esc closes.

**New workspace** (⌥N)

- Fields: project; source tabs `New branch` (base branch picker, default = the project's default branch), `Existing branch` (searchable), `Pull request` (open PRs); agent (agents with a login only); prompt (text only; attachments and @-mentions work once the workspace is open, because there is no container yet).
- `Create` calls `createWorkspace` and opens the new workspace.
- A `Keep open` checkbox keeps the dialog open for the next one, as in Conductor's Dispatcher.

**Add project**

- Lists each GitHub App installation and its repos (`listInstallationRepos`). `Link` calls `linkProject`.
- With no installation, show `Install the GitHub App` and a link to its install page.

**First-run setup** (shown until every step is done)

1. Create the GitHub App (manifest flow, 05).
2. Install it on an account or org.
3. Add a Claude login, a Codex login, or an OpenRouter key.
4. Link a repo.
5. Create the first workspace.

## Settings (⌥,)

Settings replaces the workspace frame with a full-window page. A Back button and Esc return to the workspace, preserving its mounted chat and panel state. Settings has no modal backdrop or focus trap. ⌘Enter submits the focused form. Workspace shortcuts are suspended while settings is shown; the command palette remains available.

A left sidebar has a search field for filtering navigation, Personal settings, and all linked Projects. Personal starts with General (browser notifications and sound), followed by Logins, Appearance, Shortcuts and Devices. Selecting a project expands its Agents, Scripts, Environment, Git, Prompts, Secrets and General pages. Project General contains Unlink. Project edits survive navigation between its sections until saved or reset; the Save bar remains visible with the project fields. Every field retains its effective value, source and Tempo override control. On narrow screens navigation stacks above the content. Existing settings entry points still select the requested personal section or project.

| --- | --- |
| General | Browser notifications on or off; sound on or off. |
| Devices | Sign-in sessions and Revoke (web only). |

The remaining controls retain the following content:

| Tab | Content |

## Indicators and notifications

One icon per workspace row tells you whether it needs you. Attention wins over state.

| Condition (first match) | Icon | Theme token (Tailwind v4 CSS variable) | Tooltip |
| --- | --- | --- | --- |
| `attention = needs_input` | Question mark in a circle | `--warning` | Waiting for you |
| `attention = error` | Exclamation mark in a circle | `--destructive` | Needs attention |
| `state = working` | Spinner | `--primary` | Working |
| `attention = unread` | Filled dot | `--primary` | New activity |
| `state` is `creating`, `starting`, `setting_up` or `stopping` | Small grey spinner | `--muted-foreground` | The pill text from the top bar |
| `state = sleeping` | Moon | `--muted-foreground` | Sleeping |
| Anything else | None | — | — |

**PR badge colours:** `open` green, `draft` grey, `merged` purple, `closed` red. **Checks dot:** `pending` amber, `success` green, `failure` red.

**Browser notifications** (Notification API; permission is asked from Settings, never on page load)

- Sent only when the Tempo tab is hidden.
- Events: a turn ends; a workspace enters `needs_input`; a workspace enters `error`.
- Title: `<workspace title>`. Body: `Finished`, `Waiting for you` or `Needs attention`. A click focuses the tab and opens the workspace.

**Tab title.** `(<n>) Tempo`, where n counts workspaces with attention `needs_input`, `error` or `unread`. No prefix when n is 0.

**Toasts.** Server-function errors show as a toast with the UI message from the error table. Toasts never show for errors already shown as banners.

## Keyboard shortcuts

Tempo follows Conductor's shortcuts where a browser lets a page use the key. Browsers keep ⌘N, ⌘T, ⌘W, ⌘1–9, ⌘R, ⌘L and ⌃Tab for themselves, so app actions use ⌥ instead.

**Rules**

- App actions use ⌥ (Alt). ⌘ is used only for ⌘K, ⌘B, ⌘⌥B, ⌘P, ⌘⇧F, ⌘/, ⌘U and ⌘Enter.
- Match on `KeyboardEvent.code`, not `key`. On macOS, ⌥ plus a letter types a special character; `code` stays `KeyN`.
- Call `preventDefault()` for every handled shortcut.
- On Windows and Linux, ⌘ is Ctrl and ⌥ is Alt.
- Every binding MUST be tested in Chrome on macOS. If a browser keeps a key, change the binding here first, then in code.

## Empty, loading and error states

Every screen has a defined state for nothing yet, still loading, and failed. A spinner never shows alone for more than 300 ms; after that it gets words.

| Situation | What the user sees |
| --- | --- |
| First run | The first-run setup checklist (Dialogs) |
| No projects | `Link a repo to start.` and an `Add project` button |
| Project with no workspaces | `Start a workspace` with a prompt box that opens New workspace |
| Workspace `creating` or `starting` | In the center: the op's steps as a checklist, each with its time, for example `Restoring snapshot 4 s`. The composer works; prompts queue. |
| `setting_up` | The same checklist, with the Setup tab opened in the bottom panel |
| `sleeping` | Banner: `Sleeping. Sending a message wakes it.` The Changes tab shows the last known summary; the file tree shows `Wake to browse files`. |
| `error` | Banner with the UI message, `Retry`, `Details` (shows `error_detail`) and `Archive` |
| `setup_status = 'failed'` | Banner: `Setup failed.` with `Rerun setup`, `Continue anyway` and `View output` |
| Socket lost for over 2 s | A thin bar at the top: `Reconnecting…` |
| Missing login for the chat's agent | Banner above the composer with `Add login` |
| Credential invalid | The same banner: `Your <agent> login stopped working. Add it again.` |
| Lists loading | Skeleton rows, never a blank pane |

## Phone width

Below 768 px the UI becomes one pane at a time, for checking in and replying, not for review work.

- Bottom navigation: `Workspaces`, `Chat`, `Changes`.
- `Workspaces` is the sidebar list, full width.
- `Chat` is the transcript and composer of the selected chat tab. A menu at the top switches chat tabs.
- `Changes` is the file list; a tap opens a unified diff. Review comments work.
- The primary git action shows at the top of `Changes`.
- Permission cards work as on desktop.
- No terminal, no Run output, no file tree. Each shows `Open Tempo on a larger screen for this.`
- Preview links open in a new browser tab.

## Workspace file links

Decode valid percent escapes in `file:///workspace/<path>` filenames. Ignore malformed escapes, invalid UTF-8, control characters, empty path segments and `.` or `..` segments. Invalid file links render as text and do not open a browser or a file panel. A line fragment is parsed before decoding the filename.

## Design and front-end rules

The UI is dense and quiet, like Conductor: small type, thin borders, colour only for state.

- **Components:** shadcn/ui on Tailwind v4. Icons from `lucide-react`. MUST NOT add another component library.
- **Tokens:** every colour is a CSS variable in the theme (`--background`, `--foreground`, `--muted-foreground`, `--primary`, `--destructive`, plus a custom `--warning`). No hex values in components.
- **Themes:** light and dark, following the system by default.
- **Type:** the system UI font for text; a monospace font for code, diffs and terminals. Base size 13 px in the app shell.
- **Data:** server functions through TanStack Query. Live state (items, turns, sessions, script output) lives in one store per open workspace, fed by its WebSocket and read with `useSyncExternalStore`. MUST NOT add Redux, Zustand or similar.
- **Long lists:** the transcript and file lists use TanStack Virtual once they pass 200 rows.
- **Markdown:** `react-markdown` with `remark-gfm`. Code highlighting with Shiki, loaded lazily.
- **Terminal:** `@xterm/xterm` 6.0.0 with `@xterm/addon-fit` 0.11.0.
- **Accessibility:** every action is reachable by keyboard; focus rings are always visible; new agent messages are announced with `aria-live="polite"` once per message, not per delta.
- **Storage in the browser:** only layout, sort order, viewed marks and composer drafts. Every `localStorage` read and write is wrapped in `try`/`catch`.
- **Copy:** UI text is short, plain and in sentence case. Error text comes from the error table.

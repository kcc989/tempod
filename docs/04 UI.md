# 04 UI

Native repository and issue workflows extend this client as specified in [09 Git Forge](09%20Git%20Forge.md).

This tab defines the web UI. It uses a chat-first workspace with a tool area beside the conversation.

## Layout

The sidebar stays on the left, chats stay in the center, and tools open on the right.

The workspace view has a single app-wide top bar above the sidebar, center chat tabs and right tool area. The top bar uses the existing muted surface so it is lighter than the dark content area. Its sidebar controls, workspace controls and tool tabs share one height and align with the panel widths below. No separate Tempo title row appears. Top-bar icon buttons share the same borderless style, a 24 px hit area and radius, with a neutral hover fill and visible keyboard focus. A pane toggle that is on (Info, the right side) shows a primary tint with a primary icon. Every icon-only button in the workspace view has at least a 24 × 24 px target (WCAG 2.5.8). Input, composer and control edges use `--input`, which keeps at least 3:1 against every surface (WCAG 1.4.11); `--input-fill` keeps the fainter fills. The tool-picker plus is a button, never a selected tab; active tool tabs use an underline. The sidebar and the chat/tool divider resize by dragging their edges. Sizes and visibility are kept per browser in `localStorage`, wrapped in `try`/`catch`. There is no fixed lower process panel.

## Sidebar

The sidebar lists every non-archived workspace, grouped by project, and updates live from the hub channel.

- **Structure:** a top action area with `New workspace` and `Search workspaces` (opens the command palette), separated by one thin border from the `Projects` header with sort and Add project controls. The Projects header has no lower divider. Top and footer actions use 36 px targets, normal 13 px text, 12 px icon gaps and 12 px outer padding. Project headers use a repository icon, medium 13 px foreground text and a muted 12 px workspace count. Project controls have 36 px height, an 8 px icon gap and consistent horizontal padding. Project groups have 16 px separation; workspace rows have 4 px gaps and 12 px horizontal / 8 px vertical padding. The workspace list scrolls independently above a fixed, bordered footer with full-width, left-aligned Archived workspaces, Saved chats and Settings actions. Settings shows its shortcut. These controls remain available in empty, loading and error states.
- **Sections, top to bottom:** Pinned (only if any workspace is pinned), then one section per project in `sort_order`, then an `Archived workspaces` link at the bottom.
- **Project row:** `owner/name`, a collapse toggle, and a `+` button that opens New workspace with that project picked.
- **Workspace row:**
  - Line 1: status icon (Indicators, below), then the title. The title is bold when attention is `unread` or `needs_input`.
  - One line only. The branch, slug and state label are not repeated in the row: the hover card shows Branch and State, and the row's accessible name includes the branch (unless its final segment matches the title), the slug (when it differs) and the state label (the indicator's label when attention is present, or the container state otherwise).
  - Right side: PR badge `#<number>` coloured by `pr_state`, and a checks dot when `checks_state` is set.
- **Order inside a project:** `last_activity_at`, newest first. A header menu switches to `created_at`. The choice is kept in `localStorage`.
- **Hover card** (after 400 ms): state, last activity, PR and checks, and buttons for the next action, Wake or Sleep, and Archive.
- **Right-click menu:** Rename, Pin or Unpin, Copy branch name, Open PR on GitHub when a PR exists, Archive.
- **History:** Archived workspaces lists archived workspaces with Restore and Delete. Saved chats lists retained artifacts grouped by project, including deleted workspaces. `/history?view=saved` opens Saved chats directly. Selecting a conversation opens a read-only transcript with session/agent labels, message text and expandable structured details. Lists have 100 conversations per page; saved transcripts have 100 items per page. Delete confirmation explains that saved conversations remain.
- **Width:** 240 px by default, resizable from 220 to 320 px. `⌘B` hides and shows it.
- Grouping by status is out of scope for version 1.

## Top bar

The desktop top bar is one 40 px row. It shows the branch with truncation, preview and PR links, the next git action, Info and the tool toggle. Workspace titles stay in the sidebar. Container state stays in the sidebar (status icon and hover card) and Info; `Sleeping` remains in the header as the Wake action. Startup progress appears in the transcript rather than the header. Controls never wrap below the chat tabs.

- **Left:** the branch (double-click to edit while unpushed) reveals its copy button on hover or keyboard focus, without changing layout. Workspace titles remain editable from the sidebar's context menu. Base branch selection lives in Info and shows the current base there. The picker works until a PR exists; it calls `setBaseBranch`. When `prNumber` is set, a PR link `#<number> ↗` follows, coloured by `prState`; a click opens the PR on GitHub.
- **Middle:** one link per detected port, `<port> ↗`. A click calls `openPreview` and opens the returned link in a new browser tab; the tab opens on the click, before the call returns, so pop-up blockers allow it. ⌥-click opens it in a Browser tab inside Tempo. When `browserActive` is true, a `Live` item with a red dot follows; a click opens the Live View tab.
- **Right:** the Wake pill only while sleeping, the primary action button, an Info button, and a right-side toggle button (⌘⌥B).

There is no persistent Rename branch text button. Double-clicking the branch name opens an inline editor in the same header position; keyboard activation also opens it. Copy uses a separate icon. Branch editing calls `renameBranch`; Enter or blur saves and Escape cancels. It overrides automatic first-prompt naming. The editor is enabled in ready, working or sleeping workspaces while the branch is unpushed; creation, setup and wake must finish first. The compact phone bar also permits branch editing.

Base branch options align left with consistent row padding. Long names truncate with an ellipsis. A check icon at the right marks the current base branch.

**Info panel:** Info is a freestanding, content-height card beside the chat. Info and the right tool area are mutually exclusive. The header Info button toggles the card; opening it hides tools. The right-side toggle opens tools and hides Info. Close Info hides the card without reopening tools. Opening a tool or document from Info hides the card and shows tools. Keep tool tabs and their saved width retained. Info is never a tool tab. The card is visible by default; sleeping/quiet visibility rules apply to tools. Use an inline rail capped at 360 px and 40% of the chat region's width. It starts below the workspace header and chat tab bar, which span the full workspace width. It always reserves space beside the thread, including at narrow desktop widths; it never overlays the chat. Give the card 12 px outer space, 16 px inner padding, 16 px corners and the existing muted surface. It grows with its content and scrolls only at the available height. It shows the project, live state with Wake or Sleep, changes, open chats, running scripts and available terminals, and artifacts. Each row opens related work. A Workspace controls disclosure contains branch/base selection, Copy workspace link, Environment…, Diagnostics, Reset preview access, Open in Tempo for Mac (web only), and Archive. Workspace and chat rename buttons are absent from the header and Info. Keep existing inline and context-menu editing. Phones have separate Info and Tools single-pane views with Back to chat; opening related work hides Info and shows Tools.

**Environment… dialog:** one select, `Project default (<name or None>)` plus every named environment. Choosing one calls `setWorkspaceEnvironment` at once. The dialog says `Changes apply to new requests within a minute. Scripts and agents started later get the new secrets.`

## Center: chat tabs and composer

The transcript and composer share a fluid outer track with balanced side margins, capped at 51.25rem (820 px at the default root size), including padding. With the right side closed, the web padding is 2vw, clamped from 12 to 24 px; with it open, the padding is 12 px. Markdown replies have their own 75ch reading limit and align with the composer text's leading edge. The composer, work rows and structured controls can use the wider outer track. Above the track limit, remaining space becomes balanced side margins. Smaller panes remain fluid, including when the right side opens. The transcript scroll viewport spans the full chat panel, with its scrollbar at the far right edge. Apply the reading-width limit to the message content inside the viewport. Show the scrollbar during scrolling and hide it after scrolling stops; hovering over the transcript does not show it.

The center holds one tab per open chat session. Each chat tab is one session and one agent. File, diff, Guide, Browser and Artifact tabs open in the right tool area. Opening or selecting a tool keeps the current chat and composer visible. On phones, documents still use the single-pane tab host.

**Tabs**

- New chat: ⌥T or the plus icon beside the chat tabs opens a focused composer using the same rounded surface, borderless prompt and compact model/Create chat footer as the chat composer. Close and Esc dismiss it. The icon has a `New chat` accessible label and a shortcut tooltip on every platform. Choose a reported model in its footer, then press Enter or Create chat. The model list (Settings → Models) filters the choices as in 01, Model list. Empty prompts open an empty chat; ⇧Enter adds a line. Model choices come from `listModels` and are hidden when their agent has no confirmed login. `Manage agents…` stays available while logins load or when none are configured. An explicitly selected reported model can satisfy OpenCode or Pi's model requirement.
- After the reported models, the user's agents (`listAgents`), each with its name and its base agent's name. Separate these groups only when both have entries. An agent starts a session with `createSession {agent: <base>, agentId}`. It is hidden when its base agent has no confirmed login; its own `model` can satisfy `agent.models.<agent>`, so the model rule does not disable it. The last entry is `Manage agents…`, which opens Settings → Agents.
- A chat tab from an agent shows the agent's name. Its tooltip names the base agent.
- The tab strip starts 12 px from the sidebar divider, so the first tab does not touch the edge. The active tab has a primary-color underline as well as stronger text and surface contrast. A thin divider separates the tab bar from the transcript scroll area.
- Closing a chat tab calls `closeSession`. If a turn is running, confirm first. Closed sessions stay readable under the tab bar's `Closed chats` menu. Hide the menu when the workspace has no closed chats.
- File tabs are read-only in version 1. Diff, Browser and Artifact tabs are described in the tool-area section.

**Transcript: how each item kind renders**

| Kind | Rendering |
| --- | --- |
| `user_message` | Right-aligned bubble on the muted surface, capped at 85% of the reading track, with plain text, mention chips and attachment thumbnails. Agent replies stay on the transcript surface. On hover: time and `Revert to here`, which reverts to this turn's checkpoint. |
| `agent_message` | Markdown (GitHub flavour). Code blocks get syntax highlighting with Shiki and a copy button. A caret shows while `streaming`. |
| `agent_thought` | One collapsed line, `Thinking`, that expands to the text |
| `tool_call` | One borderless row: icon by work type (below), label, status. Status shows only for `pending`, `in_progress`, `failed` and `cancelled`; a completed call shows no status icon. Expands to indented content without an outer card or divider: diffs as unified diffs, text as GitHub-flavoured Markdown. Execute text containing a Markdown fence renders as Markdown; unfenced command output keeps its line breaks and monospace formatting. Each location is a link that opens a file tab at that line. A `failed` call starts expanded. ⌃O expands or collapses all. In Default detail most calls fold into the turn's work row (below). |
| `plan` | A checklist with each entry's status. While the turn runs, a `Plan 3/4` pill also shows above the composer. |
| `permission` | A card with the title and one button per option. Enter picks the first `allow` option; ⌫ picks the first `reject` option. |
| `notice` | A small centred line, grey, amber or red by level |
| `handoff` | A collapsed notice, `Session restarted; transcript handed to the agent`, that expands to the text |
| `revert_marker` | A divider, `Reverted to turn <n>`. Reverted turns show at 50% opacity. |
| `error` | A red card with the message, the code, and a Retry button that resends the same prompt as a new turn |
| `artifact` | A card: an icon by `artifactKind`, the title, `v<version>` when the version is above 1, the file name and size, and the summary under them. Kind `image` also shows a thumbnail, at most 240 px high, from the artifact route. A click or Enter opens the Artifact tab at this version. `pending`: a spinner and `Saving`. `failed`: `This artifact was lost before it was saved.`, and no click. |

Under each turn: duration and, if the agent sends usage, tokens (`Turn.usage`: `<total> tokens`; hover shows `<input> in, <output> out`). When the turn has a work row, the work row shows the duration instead.

**Work row.** In Default detail, each turn shows one work row between the user's message and the answer. The answer stays the main content.

Work, thinking and tool disclosure labels align left with the reply text. Expanded details indent from their label; long labels truncate within the reading track.

- **What folds into it:** `agent_thought` items, `tool_call` items of type explore, run, web, sub-agent and other, and every `agent_message` of the turn except the last one. While the turn runs, the newest `agent_message` stays outside the row.
- **What stays outside, in order, after the row:** each `tool_call` of type edit, each `failed` or `cancelled` tool call, each plan proposal (below), `plan`, `permission`, `artifact`, `notice`, `error`, `handoff` and `revert_marker`.
- **Collapsed text:** the parts below that have a count above zero, joined by ` · `, then the turn duration. Example: `Explored 14 files · ran 2 commands · 48 s`. The first part starts with a capital letter.

| Part | Counts |
| --- | --- |
| `explored <n> files` | Explore calls that read or list: the distinct location paths across the row, plus 1 for each such call with no location. |
| `<n> searches` | Explore calls that search |
| `ran <n> commands` | Run calls |
| `fetched <n> pages` | Web calls |
| `ran <n> agents` | Sub-agent calls |
| `used <n> tools` | Other calls |
| `thought <n> times` | `agent_thought` items, only when nothing else is counted |

  Use the singular when n is 1 (`ran 1 command`, `1 search`).
- **While the turn runs:** the row is open and shows a spinner, the label of the newest call in it (`Thinking` when the newest folded item is a thought) and the time so far. It replaces the `Working` row. When the turn ends, the row collapses.
- **Expanded:** the folded items in order, rendered as in Detailed.
- A click or Enter toggles the row. ⌃O expands or collapses every work row and every tool call.

**Work types.** One mapping for every agent, from the ACP `toolKind` and the command:

| Type | Source |
| --- | --- |
| explore | `toolKind` `read` or `search`; or `execute` whose command is a single read, search or list command (below) |
| edit | `toolKind` `edit`, `delete` or `move` |
| run | `toolKind` `execute`, other than above |
| web | `toolKind` `fetch` |
| sub-agent | `toolKind` `think` whose `rawInput` has a string `subagent_type`, or both a string `prompt` and a string `description` |
| other | Everything else |

**Tool call labels.** Show intent, not the raw command.

1. An `execute` call whose `rawInput.description` is a non-empty string uses it as the label (Claude Code sends one with each Bash command).
2. Else, an `execute` call that is a single command maps its verb. Strip a leading `cd <dir> &&` or `cd <dir>;` first. `cat`, `head`, `tail`, `less`, `nl`, `wc` and `sed -n` give `Read <args>`. `rg`, `grep`, `find`, `fd` and `ag` give `Search <args>`. `ls` and `tree` give `List <args>`. A command is single when it has no `;`, `&&`, `||`, newline or `|`, except a pipe into `head` or `tail`.
3. Else, the ACP `title`, in monospace when the call is `execute`.

The label is one line and truncated with an ellipsis. Its tooltip is the full title.

**Edit rows.** An edit call shows its file name and `+<added> −<removed>`, counted from its diff content. A `Changes` link on the row opens the Changes tab.

**Plan proposals.** A `tool_call` whose `rawInput.plan` is a non-empty string is a plan proposal, for example Claude Code's `ExitPlanMode`. It renders as a card titled `Plan`, with `rawInput.plan` as Markdown, expanded. A `permission` item for the same `toolCallId` shows its buttons under that card. Spike S18 MUST record which agents send `rawInput.plan`.

**Detail.** Settings → Appearance → Transcript detail: `Default` or `Detailed`. Detailed shows every item as its own row, as before the work row. Both show edits and failures as their own rows.

**Composer**

The text field and bottom toolbar share one rounded, subtly tinted container with a thin border and a soft offset shadow. Focusing the input does not add an outline or change the container border or shadow. The input starts with two lines of breathing room and grows with the draft. One compact, borderless model picker sits at the lower left; context usage, the `+` attachment button and send controls sit at the lower right. The focus shortcut is listed in the command palette and Shortcuts, not in the input. Queue and plan chips remain above the container; attachment, mention and review chips sit inside it above the text.

- Enter sends. ⇧Enter adds a new line.
- While a prompt submission is pending, Enter, Send, Queue and Send now cannot submit another prompt for that session. Switching tabs does not remove this guard. If submission fails, restore the prompt unless the owner has already typed a new draft.
- While a turn runs, Enter queues the prompt. Queued prompts show above the composer as chips; each can be edited, deleted or dragged.
- The workspace's first accepted prompt (`Turn.seq = 1`) appears once as a normal user message in the transcript while the workspace and agent start. It stays there when the turn starts, and has no queue chip or Edit/Delete row. The workspace status shows startup progress. Later queued prompts keep their queue controls; reordering them keeps the initial prompt in its queue position. Deleted turns disappear, and failed startup retains the message beside the existing workspace error and recovery controls. This changes presentation only: the server turn remains `queued` until the agent accepts it.
- When the current chat's running adapter advertises steering, show a separate **Send now** button. It delivers the message into that turn without stopping it. Enter still queues. If the turn ends before delivery, the message stays queued. An unconfirmed delivery shows an error and requires the user to check the response before retrying.
- A message with `steeringPending` shows **Sending now**. Disable its queue controls until delivery settles.
- A Stop button shows while a turn runs. Esc in the composer also stops it.
- `@` opens a fuzzy file picker over `listFiles` and inserts a mention chip.
- `/` opens a menu of the agent's own commands plus Tempo's `/plan`, which toggles plan mode. While the menu is open, Up and Down choose an entry, Enter selects it, and Esc closes the menu without stopping the turn.
- Attach with paste, drag and drop, or ⌘U. Each file at most 10 MiB.
- Model picker: models come from the agent's `model` config option. The same menu contains a `Thinking` submenu from the `thought_level` option, an advanced `Mode` submenu from the agent's modes or mode config option, and its other settings. Hide unavailable settings. The trigger shows the model and a non-default thinking level; it has no separate reasoning, mode or options control. Changes use the existing `setSessionConfig` and `setSessionMode` calls and show the returned values. New chats keep the agent's normal automatic workflow; do not preselect planning or replace an explicit saved mode. Use agent-reported names and values, including Auto when reported. ⇧Tab still toggles plan mode.
- When `Session.profileIssues` is not empty, a notice above the composer reads `<base agent> ignored some settings of <agent>: <list>`, with the issue names shown as `system prompt`, `tool limits`, `MCP servers`, `model` and `reasoning level`. It can be dismissed per session.
- Draft review comments show as one chip, `<n> review comments`. They are sent with the next prompt.
- A compact, unlabeled context button with a 48 × 6 px horizontal capacity meter shows usage when the agent sends a valid `usage_update`. Its neutral fill is proportional to used / total tokens, clamped at full. It has no loading animation, invented usage breakdown or warning threshold. Hover or keyboard focus exposes the percentage and token totals; clicking or keyboard activation opens details with the percentage, exact totals and an explanation of the fill. Hide it until usage is known. Inside the model picker, Thinking and Mode rows show their current value and open nested choices.
- The draft text is kept per session in `localStorage`.
- Unsent mention, attachment and review-comment chips stay with their session when switching tabs. Draft storage may include their metadata and server references; file bytes and preview URLs stay in memory.
- Archived workspace: the composer is replaced by `Restore to continue`. Missing login: a banner with `Add login`.
- Pending environment proposals (01, Environments): a banner above the composer, `The agent suggests environment changes`, with **Review**. Review opens a dialog for the oldest pending proposal. It shows the agent's note, then each change as a list: policy, hosts to add, secrets with their `hosts`, and injectors with their full code (read-only, monospace). Each new secret, and each listed secret with no stored value, has a value field. The dialog names the target: `Apply to <environment name>`, or, with no environment, `Create environment <repo name> and use it for this project`. **Apply** writes the changes with `createEnvironment` (if needed), `setProjectEnvironment` (if created), `updateEnvironment` and `setEnvironmentSecret` for each filled value, then `resolveEnvironmentProposal` with `applied`. **Dismiss** calls it with `dismissed`. The dialog warns `Injectors run with access to these secrets. Read the code before you apply.` when the proposal has injectors.

## Right tool area

The right side shares the app-wide top bar for its tool and document tabs. The `+` button opens a two-column Tools grid of flat, rounded rows with an icon and left-aligned label: Terminal, Run, Browser, Guides, Artifacts and Activity. Changes is not in the grid; it opens from Info and from actions that target it. Rows use 36 px height, normal body text and compact padding. Tool tabs and section tabs start 12 px inside the pane edge, and the workspace controls end 12 px before it. Show shortcut hints only for existing commands. Info is available from its top-bar toggle and is absent from this grid. Changes contains Changes, Files and Checks sections. Run contains Setup and Run sections. Each group has one outer tab and close control; section tabs appear within it. Selecting a section never adds a second outer tab. Switching outer tabs preserves the group's last section. The initial view is the Tools grid. Opening the pane with its toggle returns to the grid while preserving open tool tabs. Actions that target a tool open that tool directly. Files, diffs, Guide and artifacts can still open their own document tabs. Closing the active tab shows the grid. Browser renders the Cloudflare Browser Run Live View; it is not a general browser. Terminal and Run keep their connections and output while another tool or section is selected or Info changes visibility. Each terminal is its own outer tab, named `Terminal <n>` for terminal id `t<n>`; there is no inner terminal tab list. Outer tabs keep the order they were opened in. Terminal in the grid opens a new terminal tab for the lowest id from `t1` to `t9` that has no open tab; an existing tmux session with that id keeps its shell and scrollback (01). With nine terminal tabs open, the grid's Terminal row is disabled with the tooltip `Nine terminals are open`. Closing a terminal tab closes its connection; the tmux session keeps running. ⌘⌥B toggles only the tool area; ⌥J selects the most recently used terminal tab, opens a new one when none is open, or returns to the launcher when a terminal tab is selected.

The right side starts closed when the workspace is `sleeping`, or when it has no changes and no PR. It opens by itself when changes or a PR appear. ⌘⌥B, ⌥J, or any action that shows a tool tab opens it for that workspace until the page reloads; closing it with ⌘⌥B is kept as the layout choice.

**Changes tab**

- A file list with status letter (`A`, `M`, `D`, `R`) and `+`/`−` counts, from `getChanges`. It refreshes on every `changes` message.
- Scope toggle: `Branch` (against the merge base with `origin/<base>`) or `Uncommitted` (against `HEAD`). ⌥U switches.
- `Group by folder` toggle.
- A click opens the Diff tab at that file.
- Footer: a commit message field and `Commit and push`.

**Diff tab** (right tool area)

- Unified or split view, kept in `localStorage`. Unified only below 1024 px wide.
- J and K move to the next and previous file when focus is not in a text field.
- Image files (PNG, JPEG, GIF, WebP, AVIF, SVG) show `Before` and `After` images side by side (stacked below 1024 px) instead of a text diff. `Before` comes from `readFileAt` with `baseSha` (branch scope) or `headSha` (uncommitted scope); `After` comes from `readFile`. An added file has no `Before`; a deleted file has no `After`. SVG renders only through `<img>`. File-level comments work; line comments do not apply.
- `Mark as viewed` per file (⌃V). The mark is stored in `localStorage` with the file's diff hash, so it clears when the diff changes.
- Comments: click a line number, or drag across several, to add a comment. A file-level comment button sits in each file header. Comments are `draft` until sent with a prompt.
- A `Send <n> comments to <agent>` button puts the drafts into the composer as one chip.

**Artifacts tab**

- One row per artifact, newest version first: icon by kind, title, `v<version>`, the chat tab's title, and the time. Older versions show inside the row's version menu, not as rows.
- Loaded with `listArtifacts`, again on every `item.upsert` of kind `artifact`. It works while the workspace sleeps and after archive, and never wakes it.
- A click opens the Artifact tab.
- Empty state: `No artifacts yet. Pages and files that agents publish appear here.`

**Artifact tab** (right tool area)

- One tab per artifact. The header shows the title, a version menu (newest first, newest selected), the file name, `Download` (the artifact route with `?download=1`) and `Reload`. When `path` is under `/workspace`, the file name is a link that opens a file tab.
- **`image`:** an `<img>` from the artifact route, fit to the tab, with click to zoom to 100 %. SVG MUST render only through `<img>`, never inline and never in `<object>` or `<iframe>`.
- **`markdown`:** fetched from the artifact route as text and rendered with the transcript's Markdown rules (no raw HTML, no remote images), plus Mermaid (Design and front-end rules).
- **`text`:** monospace with Shiki highlighting by file extension, as a file tab.
- **`pdf` and `html`:** an iframe that loads the link from `openArtifact`, as the preview Browser tab. `Open in new tab` opens the same kind of link in a browser tab. HTML iframes have `sandbox="allow-scripts allow-forms allow-modals allow-downloads"`; S18 MUST confirm that the entry cookie works with these attributes.
- A version still `pending` shows `Saving…` and loads when its item becomes `completed`. A `failed` version shows `This artifact was lost before it was saved.`

**Guide tab** (right tool area)

- `Guides` in Info and the tool launcher opens one Guide tab per workspace. Contextual Guide actions in Changes and Diff remain available. `/w/<workspaceId>?guide=true` opens it directly; `Copy link` copies this owner-authenticated link, not a public preview capability.
- `Create guide`, `Update guide` and `Repair guide` send the shared authoring prompt in `packages/protocol/pr-guide-prompt.txt` to the current or most recently shown chat via `sendPrompt`. Normal queueing, credentials, permission requests, errors and transcript behavior apply. With no chat, tell the user to open one. Disable authoring while archived, sleeping, without an available session, or while the requested turn is active.
- The agent inspects the user's branch diff and writes `.tempo/pr-guide.json` plus optional repository artifacts. This is a feature for users' repositories; no guide is generated automatically for Tempo's own code. The prompt does not authorize application code changes, committing, pushing or opening a PR.
- The version 1 repository format is defined by `PrGuide` in `packages/protocol/src/pr-guide.ts`. It has `title`, Markdown `summary`, Markdown `before` and `after`, and ordered `chapters` with unique `id`, `title`, Markdown `description`, repository-relative `files`, and zero or more `visuals`. Each guide and artifact uses `readFile` and its existing limit. Invalid versions, unsafe paths, duplicate chapter/node ids and dangling flow edges show a repair state.
- The chapter list stays beside the explanation, its visuals and its live branch diffs on desktop; narrow screens stack them. Previous and Next navigate chapters. The overview has a before/after comparison with Before, After and Side by side controls. Files missing from the live diff are identified; every changed file absent from the guide stays reachable under `Files outside guide`. A guide never hides unmentioned changes or claims that its explanation is current. Tell users to verify the live diff and update after code changes.
- Diffs reuse viewed marks keyed by the diff hash and draft comments, including Send comments. Guides refresh on workspace changes and completed turns; `Refresh` retries explicitly. Sleeping workspaces show the last loaded guide with a cached-state note and a Wake action before fetching files or diffs.
- Visuals: `comparison` (Markdown before/after); `flow` (selectable labeled nodes, connections and node explanations with optional file links); `markdown`, `image` or `html` (a titled repository artifact, optional caption). Multiple visuals may explain one chapter. Artifacts load only on `Open artifact`. Images are inline data from PNG, JPEG, GIF or WebP files. Markdown follows the existing no-HTML/no-remote-images rules. Interactive HTML is self-contained and isolated as specified in 05.
- The chapter list, overview, chapter description, visuals and Previous/Next are one shared component. A native repository PR detail renders the committed guide with it, reading files from the PR's head ref with `getRepositoryFile` instead of `readFile`, with file links into the repository Code tab and no diffs (09, Web and Mac, PR guide).
- `Create guided PR` uses `createPullRequest` with the guide title, summary and an `Open guided review in Tempo` link. It is enabled only after the guide and artifacts are committed and pushed, with no uncommitted changes or unpushed commits, and with no open/draft PR. Normal PR creation remains available. For existing PRs, users can copy the guide link. PR body links require the Tempo owner's login; collaborators can also inspect committed artifacts on GitHub.

## Keyboard shortcuts

Tempo follows Conductor's shortcuts where a browser lets a page use the key. Browsers keep ⌘N, ⌘T, ⌘W, ⌘1–9, ⌘R, ⌘L and ⌃Tab for themselves, so app actions use ⌥ instead.

**Rules**

- App actions use ⌥ (Alt). ⌘ is used only for ⌘K, ⌘B, ⌘⌥B, ⌘P, ⌘⇧F, ⌘/, ⌘U and ⌘Enter.
- Match on `KeyboardEvent.code`, not `key`. On macOS, ⌥ plus a letter types a special character; `code` stays `KeyN`.
- Call `preventDefault()` for every handled shortcut.
- On Windows and Linux, ⌘ is Ctrl and ⌥ is Alt.
- Every binding MUST be tested in Chrome on macOS. If a browser keeps a key, change the binding here first, then in code.

## Workspace file links

Decode valid percent escapes in `file:///workspace/<path>` filenames. Ignore malformed escapes, invalid UTF-8, control characters, empty path segments and `.` or `..` segments. Invalid file links render as text and do not open a browser or a file panel. A line fragment is parsed before decoding the filename.

## Design and front-end rules

The UI is dense and quiet, like Conductor: small type, thin borders, colour only for state. Surface depth comes from the existing background, sidebar, card, muted and popover tokens, thin boundaries and popup elevation.

- **Components:** shadcn/ui on Tailwind v4. Icons from `lucide-react`. MUST NOT add another component library.
- **Tokens:** every colour is a CSS variable in the theme (`--background`, `--foreground`, `--muted-foreground`, `--primary`, `--destructive`, plus a custom `--warning`). No hex values in components.
- **Themes:** light and dark, following the system by default. Use the existing palette consistently: sidebar for navigation, background for the chat canvas, card for supporting panels, muted for the composer, and popover for floating menus. Hover and selected states remain distinct. Floating menus have an offset shadow and a thin boundary; keep body and muted text readable on every surface.
- **Type:** the system UI font for text; a monospace font for code, diffs and terminals. Base size 13 px in the app shell.
- **Data:** server functions through TanStack Query. Live state (items, turns, sessions, script output) lives in one store per open workspace, fed by its WebSocket and read with `useSyncExternalStore`. MUST NOT add Redux, Zustand or similar.
- **Jump to latest:** when the reader scrolls up, a `Jump to latest` button shows centred 8 px above the composer. It has an opaque `--background` fill, a border and a shadow, so text under it never shows through.
- **Long lists:** the transcript and file lists use TanStack Virtual once they pass 200 rows.
- **Markdown:** `react-markdown` with `remark-gfm`. Code highlighting with Shiki, loaded lazily in the browser after hydration. Server renders stay plain; browser-only grammars must not enter the Worker bundle.
- **Mermaid:** in every Markdown view (agent messages, Markdown artifacts, Markdown file previews), a fenced code block with the language `mermaid` renders as a diagram with `mermaid` 12.1.0, loaded lazily in the browser after hydration. Server renders stay as code; browser-only diagram libraries must not enter the Worker bundle. Initialize it with `startOnLoad: false`, `securityLevel: "strict"` and HTML labels off (S18 records the exact config keys for 12.1.0), call `mermaid.render`, then show the SVG only through `<img>` from a `data:image/svg+xml` URL, never inline. Follow the theme. While a message streams, keep the code block until the item is `completed`. If rendering fails, show the code block and `Diagram failed to render.` under it.
- **Terminal:** `@xterm/xterm` 6.0.0 with `@xterm/addon-fit` 0.11.0.
- **Accessibility:** every action is reachable by keyboard; focus rings are always visible; new agent messages are announced with `aria-live="polite"` once per message, not per delta.
- **Storage in the browser:** only layout, sort order, theme, transcript detail, viewed marks, the Markdown source or preview choice and composer drafts. Every `localStorage` read and write is wrapped in `try`/`catch`.
- **Copy:** UI text is short, plain and in sentence case. Error text comes from the error table.

# S11: Can GPUI Kit 0.7.1 carry the Tempo transcript?

Status: **partly run.** Everything that can run on the Linux build machine ran. The frame-time
criterion (p99 under 16 ms on an M1) needs a Mac and is **not measured yet**; the harness for it
is ready (below).

The spike code is the real start of `apps/mac` (crate `tempo-mac`, binary `Tempo`), plus one
example binary, `apps/mac/examples/s11_transcript.rs`.

## Build on Linux

The build machine is Ubuntu 24.04 x86_64. `cargo check` needs nothing beyond what the image
already had (`pkg-config`, `clang`, `cmake`, X11/XCB, fontconfig, freetype and Wayland client
libraries). Linking (`cargo test`, `cargo build`) also needs:

```sh
apt-get install -y --no-install-recommends libxkbcommon-dev libxkbcommon-x11-dev
```

(`libxkbcommon-x11-dev` pulls in `libxcb-xkb-dev`.) No other package was installed.
Running the window on Linux would also need a display server and a Vulkan driver; not tried.

macOS-only code (`src/macos/`: Keychain, notifications, Dock badge, wake events) sits behind
`#[cfg(target_os = "macos")]`; `src/platform.rs` gives every caller one API with an in-memory or
no-op fallback, so the crate builds and tests on Linux. `src/macos/` is std-only stubs today; it
is the only module allowed `unsafe` (`#![deny(unsafe_code)]` at the crate root).

Dependencies added to `apps/mac/Cargo.toml`, both pinned: `gpui-kit = "=0.7.1"` and
`async-channel = "=2.5.0"` (07, Data flow names it; already in GPUI's tree). Cargo feature
`profiler` turns on `gpui-kit/profiler` for the frame-time harness only.

## GPUI Kit 0.7.1 APIs, as used

`gpui-kit` 0.7.1 depends on `gpui-pre = "=0.3.8"` (a GPUI snapshot) and re-exports it:
`use gpui_kit::*` is GPUI; `gpui_kit::component` is `gpui-component` 0.7.1; `gpui_kit::base` is
`gpui-base` 0.7.1. Do not depend on `gpui` or `gpui-pre` directly: GPUI's macros rewrite `gpui::`
paths to the `gpui-kit` facade.

**Start-up** (`src/main.rs`)

```rust
gpui_kit::application()
    .with_http_client(image_policy::blocked_http_client())
    .on_open_urls(..)          // tempo:// URLs; the callback has no App, so it sends on a channel
    .run(|cx| {
        gpui_kit::init(cx);    // theme, Root plugins, input and component key bindings
        app::init(..);         // AppState global, app-level actions
        keymap::bind(cx);      // after init, so ours outrank GPUI Kit's at equal depth
        menus::set(cx);
        views::main_window::open(..);
    });
```

**Actions** (`src/actions.rs`)

- Unit actions: `gpui_kit::actions!(tempo, [CommandPalette, NewWorkspace, ..])`. Names are
  `tempo::CommandPalette` etc.
- Actions with data: `#[derive(Clone, PartialEq, Action)] #[action(namespace = tempo, no_json)]
  pub struct SwitchToWorkspace(pub usize);`. `no_json` avoids serde and schemars derives.
- Handlers: app-wide `cx.on_action(|_: &Quit, cx| cx.quit())`; in a view
  `.on_action(cx.listener(|this, _: &ToggleSidebar, window, cx| ..))`. Dispatch from code with
  `window.dispatch_action(Box::new(action), cx)`.

**Key bindings and contexts** (`src/keymap.rs`)

- `cx.bind_keys([KeyBinding::new("cmd-k", CommandPalette, Some("Workspace")), ..])`.
- A context is set with `.key_context("Workspace")` on an element that also
  `.track_focus(&focus_handle)`; bindings apply while focus is inside it.
- Precedence: the deepest matching context wins; at equal depth the binding added later wins.
- Predicates support `A > B` (B inside A). GPUI Kit's text fields use context `Input`, which
  binds enter, escape, tab, shift-tab, up and down. The composer binds Send, StopTurn and
  TogglePlanMode on `Composer > Input` so they outrank the field. ⇧Enter keeps the field's own
  newline binding.
- `NoAction` unbinds a key in a context. The `Terminal` context binds tab, shift-tab, ctrl-tab,
  ctrl-shift-tab and ctrl-o to `NoAction`, so every key that is not a ⌘ shortcut reaches the
  shell (07). Tab and shift-tab matter: GPUI Kit's `Root` binds them to focus traversal.
- Keystroke syntax: `cmd`, `ctrl`, `alt`, `shift`, `fn`, and `secondary` (⌘ on macOS, Ctrl
  elsewhere), joined with `-`: `cmd-alt-down`, `cmd-shift-backspace`, `cmd-,`, `cmd-/`.
  `Keystroke::unparse` orders modifiers fn, ctrl, alt, cmd, shift, and prints `super` for cmd on
  Linux.
- Contexts used: `Workspace`, `Composer`, `Diff`, `Terminal` (07). Tests check the Conductor
  column of 04 and that no key repeats within a context.

**App menus** (`src/menus.rs`)

- `cx.set_menus(vec![Menu::new("Tempo").items([MenuItem::action("About Tempo", About),
  MenuItem::separator(), ..]), ..])`. The first menu is the app menu on macOS.
- Edit items use `MenuItem::os_action("Copy", gpui_kit::component::input::Copy, OsAction::Copy)`,
  so text fields and the system agree. `MenuItem::os_submenu("Services", SystemMenuType::Services)`
  exists; 07's table does not list Services, so it is not added.
- Menus show the shortcut of the binding found for the action in the keymap. To verify on a Mac
  that context-bound (`Workspace`) shortcuts appear in the menus.

**Root and TitleBar**

- `gpui_kit::open_window(options, cx, |window, cx| cx.new(..))` wraps the view in
  `gpui_kit::base::Root` (also `gpui_kit::component::Root`) and returns
  `(AnyWindowHandle, Entity<View>)`. Root hosts dialogs, sheets, notifications and tooltips:
  `window.open_dialog(cx, |dialog, _, _| ..)`, `window.push_notification(..)` (`WindowExt`).
- `TitleBar::new().child(..)` with `WindowOptions { ..TitleBar::window_options() }`: transparent
  title bar, traffic lights at (9, 9), 80 px left padding on macOS, height 34 px, and the title
  bar handles dragging (`app_owns_titlebar_drag: true`).
- Theme: `Theme::sync_system_appearance(Some(window), cx)` and
  `cx.observe_window_appearance(window, ..)` follow the macOS appearance.
  `Theme::change(ThemeMode::Dark, None, cx)` forces one.

**Resizable**

`h_resizable("main-panes").child(resizable_panel().size(px(280.)).size_range(px(220.)..px(400.))
.visible(open).child(sidebar)).child(resizable_panel().child(center))`, and `v_resizable` for the
right side. `.with_state(&Entity<ResizableState>)` and `ResizableState::sizes()` read the sizes
for `state.json`; `.on_resize(|state, window, cx| ..)` reports changes.

**Sidebar**

`Sidebar::new("sidebar").collapsible(false).footer(..).children([SidebarGroup::new("acme/api")
.child(SidebarMenu::new().children([SidebarMenuItem::new(title).active(b).on_click(..)
.suffix(..).context_menu(..)]))])`. Its default width is 255 px; inside a resizable panel it
takes `.w_full()`. Custom rows implement the `SidebarItem` trait.

**Tabs**

`TabBar::new("center-tabs").selected_index(ix).on_click(cx.listener(|this, ix: &usize, _, cx|
..)).children(labels.map(|l| Tab::new().label(l)))`. Variants: `pill`, `outline`, `segmented`,
`underline`; `.prefix`, `.suffix` (for the `+` button) and `.menu(true)` for overflow.

**MessageScroller**

```rust
let state = cx.new(|cx| MessageScrollerState::new(rows.len(), cx)); // follows the tail
MessageScroller::new("transcript", state.clone(), move |ix, window, cx| render_row(ix))
state.update(cx, |s, cx| s.append(1, cx));            // new item
state.update(cx, |s, cx| s.remeasure_items(ix..ix + 1, cx)); // item.delta: that row only
```

It is GPUI's `list` with 400 px overdraw; `scroll_to_end`, `is_scrolled_up`, `prepend`, `splice`
and a jump-to-latest button (`.jump_button(true)`) exist. Each chat tab keeps its own state
entity, so each keeps its own scroll position.

**TextView**

`gpui_kit::component::text::TextView::markdown(id, text).selectable(true)
.on_link_click(|url, event, window, cx| ..)`. GFM, math, `code_block_actions` (copy button) and
`stream_fade` exist. `TextView::markdown` with a stable id keeps its parsed state per row and
appends when the new text extends the old.

## Raw HTML (07 R14)

`TextView::markdown` passes HTML nodes from `markdown-rs` to an html5ever parser and renders
them: `<img>` (loads its `src`), `<a href>`, tables, headings, `<br>`, and `<b>`, `<i>`, `<u>`,
`<s>`, `<mark>`, `<code>` inline. MDX mode turns off HTML constructs, but it parses `{..}` and
JSX and fails on stray `<` or `{`, so it does not fit agent text.

`src/markdown.rs` (`escape_raw_html`) replaces every `<` with `&lt;` unless it is inside a fenced
code block or an inline code span. Where the block structure is ambiguous (a fence behind a list
or quote marker, a less indented line inside an indented fence, a backtick span that may cross
lines or table cells), it escapes more, never less: the worst case shows `&lt;` inside code. A
`\<` is left alone; CommonMark already shows it as text. Deltas are escaped as the row's text
grows (`TranscriptRow::push_delta`).

## Remote images (07 R14)

1. `src/image_policy.rs` `LocalImageCache` implements `ImageCache`: `Resource::Uri` returns
   `Some(Err(ImageCacheError::Asset(..)))`; paths and embedded assets go to a
   `RetainAllImageCache`. Every string that parses as a URL becomes `Resource::Uri` and is fetched
   with `cx.http_client()` whatever its scheme (`data:` and `file:` too), so all URIs are refused,
   not only http and https.
2. **Finding:** GPUI's `ImageCacheElement` puts its cache on the window's stack only in
   `request_layout` and `paint`, not in `prepaint`. `img` reads the stack when it lays out.
   `list` (so `MessageScroller`) lays out rows in `prepaint`, and `TextView` lays out inline
   images with `prepaint_as_root`, so both miss a cache that wraps the transcript and fall back
   to `window.use_asset::<ImgResourceLoader>`, which fetches remote URLs.
3. So: each transcript row is wrapped in `image_cache(..)` (covers images laid out in the row's
   `request_layout`), and the app replaces GPUI's HTTP client with
   `http_client::BlockedHttpClient` (`Application::with_http_client`). The app does all its
   networking on tokio (07, C6), so GPUI never needs the network. This closes every path,
   including ones outside the transcript.
4. `gpui_kit::base::TextView` (not the component wrapper) has `.image_source(|uri| ImageSource)`,
   which could also map remote URIs to an error image. Not used.

Still to do (M2): show refused images as links (07). Today a refused image renders nothing.

## Links

`src/links.rs`: http and https open in the default browser (`cx.open_url`);
`file:///workspace/<path>` dispatches `OpenWorkspaceFile(path)` (a `..` or empty segment is
ignored); every other scheme is ignored.

## Module skeleton laid out (07, Architecture)

`src/main.rs`, `src/app.rs` (AppState: server URL, auth state, HubStore, open workspaces with the
5-store LRU, sign-out), `src/client.rs` (stand-in for `tempo_client::Runtime` until
`crates/tempo-client` has one), `src/stores/{hub,workspace}.rs` (stubs; they take generated
`tempo-protocol` types later), `src/views/` (sidebar, top_bar, chat, composer, changes, diff,
files, checks, setup, run, terminal, dialogs, settings, palette, tokens, main_window),
`src/macos/`, `src/platform.rs`, `src/url_scheme.rs`, `resources/Info.plist`
(`dev.tempo.mac`, `LSMinimumSystemVersion` 15.0, `CFBundleURLTypes` `tempo`) and
`resources/Tempo.entitlements` (no keys: hardened runtime comes from `codesign --options runtime`,
no exceptions, no App Sandbox). `AppIcon.icns` is not made yet.

`src/views/tokens.rs` maps 04's tokens once: `--primary` → `ThemeColor::primary`,
`--destructive` → `danger`, `--warning` → `warning`, `--muted-foreground` → `muted_foreground`
(plus background, foreground, border, and `success` for added diff lines).

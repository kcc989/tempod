# S13: Can `gpui-terminal` run on GPUI Kit's GPUI and a socket?

Status: **feasibility check only.** No fork yet (as asked). Running `vim` and `htop` over the
terminal channel, resizing and restoring after a reconnect need the fork, a deployed Tempo and a
Mac; not run.

## Does `gpui-terminal` 0.1.0 build against GPUI Kit's GPUI (`gpui-pre` 0.3.8)?

**Not as published.** `gpui-terminal` 0.1.0 depends on `gpui = "0.2.2"`, the GPUI release on
crates.io, not on `gpui-pre` 0.3.8, which `gpui-kit` 0.7.1 bundles.

- Cargo resolves both in one graph (checked with `cargo generate-lockfile` on a crate that
  depends on `gpui-kit = "=0.7.1"` and `gpui-terminal = "=0.1.0"`: `gpui` 0.2.2 and `gpui-pre`
  0.3.8 side by side, 974 packages). That does not help: its `TerminalView` would be a GPUI 0.2
  entity, which a GPUI Kit window cannot hold, and two GPUI platform layers cannot share one
  `NSApplication`. So the fork is required, as 07 (C8) says.
- Port attempt (scratch copy outside the repo, not a fork): the library sources unchanged, with
  `gpui = { package = "gpui-kit", version = "=0.7.1" }` so `use gpui::*` resolves through the
  facade, `alacritty_terminal = "=0.25.1"`, and the PTY demo binary dropped.
  Result: **2 compile errors, both one-line API changes**, then `cargo check` passes with no
  warnings (Rust 1.97.0, Linux):
  - `ShapedLine::paint(origin, line_height, window, cx)` now takes
    `(origin, line_height, align: TextAlign, align_width: Option<Pixels>, window, cx)`; pass
    `TextAlign::Left, None` (`render.rs`).
  - `Window::focus(&handle)` now takes `(&handle, cx: &mut App)` (`view.rs`).

  So the port is small. It was only checked, not run: a type-checked port can still differ at
  run time (text shaping, input events, the element lifecycle).

## What the crate is

- License MIT OR Apache-2.0, with `LICENSE-MIT` and `LICENSE-APACHE`. The source files carry no
  per-file license headers. Author: Leonard Seibold. Repository: github.com/zortax/gpui-terminal.
  The fork keeps both license files and adds a note that names the origin.
- About 5,000 lines: `view.rs` (the `TerminalView` entity), `render.rs` (cell batching and
  painting with `shape_line` and `paint_quad`), `terminal.rs` (wraps `alacritty_terminal`'s
  `Term`), `input.rs` (keystroke to bytes, application cursor mode), `mouse.rs` (mouse reporting,
  a `SelectionType` enum), `colors.rs`, `clipboard.rs`, `event.rs`.
- Dependencies: `alacritty_terminal` 0.25.1 (07 pins `=0.25.1`), `anyhow`, `flume`,
  `parking_lot`, `ropey` 1, `arboard` 3 (clipboard, X11 and Wayland), and `portable-pty` 0.9 for
  the demo binary only.
- I/O: `TerminalView::new(writer: impl Write, reader: impl Read, config, cx)`. A thread reads
  the `Read` and a GPUI task feeds the parser. Resize goes out through
  `with_resize_callback(cols, rows)`.

## What the fork changes (`crates/tempo-terminal`)

1. `gpui = "0.2.2"` → `gpui-kit = "=0.7.1"`, and fix the API differences the port attempt lists.
2. Replace the `Read`/`Write` pair with the terminal channel (02): received frames go to the
   parser; keystrokes and resizes go out on the same socket (01, Terminal). The socket lives on
   the tokio runtime in `tempo-client`; the view reads an `async_channel` receiver in a
   foreground task, like the stores (07, Data flow).
3. Drop `arboard` and `portable-pty`. Clipboard goes through GPUI (`cx.write_to_clipboard`), so
   no X11 or Wayland clipboard crates enter the Mac build.
4. Add mouse selection and ⌘C copy (07). The crate has a `SelectionType` enum, but its mouse
   handlers are `TODO: Implement mouse selection`, and clipboard integration is a TODO too.
5. Scrollback 10,000 lines (`alacritty_terminal::term::Config::scrolling_history`), and wheel
   scrolling, which is a TODO in 0.1.0.
6. Key context `Terminal`: the app keymap already unbinds every non-⌘ key bound outside it
   (`apps/mac/src/keymap.rs`, `TERMINAL_PASSTHROUGH`), so those keys reach the shell.
7. Element id, `a11y_role()` and `aria_label` on the terminal element (07, custom controls).

07's license rule holds: `gpui-terminal` and `alacritty_terminal` are MIT or Apache-2.0; nothing
comes from Zed's GPL `terminal_view`.

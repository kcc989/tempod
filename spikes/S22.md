# S22: Clef-flash Worker binding

Status: passed on 2026-10-13, before the decision implementation. Starting repository SHA: `3edf1f6fd8422b6d6aa4bac7f539c8920cb520ff`.

A temporary, isolated Worker used one `AI` binding and synthetic input only: a 4,096-byte state and four `noul` questions. Timing surrounds `env.AI.run` inside the Worker; it excludes the caller-to-Worker hop. The accepted batch has 50 valid measured calls, min 353 ms, median 411 ms, nearest-rank p95 878 ms, maximum 984 ms. One separate dot-ID probe preceded these measurements. Every temporary Worker was deleted, and deletion returned success. The production Tempo Worker and its storage were unchanged.

The first batch issued 50 calls: 49 returned valid model responses and one returned Cloudflare edge error 1042 without a model latency. Its 49 measured responses had p95 841 ms and max 1,214 ms. It is not the passing 50-call sample. The second batch was a fresh measurement, not a retry added to an application call or a test.

Direct REST inference returned HTTP 401/code 10000 with the managed credential, while Worker upload, binding inference and deletion succeeded. Early HTTP probes also encountered Cloudflare 1010/1042 and one disconnected connection. A synthetic health response established Worker readiness before measurement. These transport checks are separate from binding latency.
